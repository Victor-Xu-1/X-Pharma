# X-Pharma 源码梳理

## 模块职责与调用关系

靶点管线的 `PipelinePrimaryFilters.css` 单独拥有窄屏常用筛选布局：
保留五个全宽字段和原来的 DOM/键盘顺序，以并排的标签与控件降低首屏占用。
不隐藏筛选、不取得查询状态权威；原有单列字段宽度验收继续保留，
追加窄屏整体高度与六个原控件的 44px 点击区域验收。

| 边界 | 权威模块 | 职责 |
| --- | --- | --- |
| 应用进程 | `gateway.py`、`jobs.py`、`job_roles.py` | 单网关和受监督后台角色 |
| Web/API | `api.py`、`http/`、`security.py`、`human_oidc.py` | 应用组装、分域传输、人员/Agent 身份与 scope |
| 账号与组织 | `accounts/` | 全局身份、组织成员权限、独立 viewer 空间、邀请确认、事务领取、管理员权限与请求预算 |
| 领域查询 | `intelligence/`、`repository.py`、`dossier.py` | Web 与 MCP 共用的事实查询 |
| 数据库 | `models/`、`schemas/`、`db.py`、`migrations/` | 按领域归属的数据模型和传输契约、事务和签名 RLS |
| 数据工厂 | `ingest/commands/`、`ingest/` | 应用写入、来源、快照、安全解析、Temporal 和恢复 |
| AI 治理 | `governance/`、`enterprise/llm_providers.py` | 模型访问、暂存、验证、审核与发布 |
| 检索与知识 | `search/`、`knowledge/` | outbox delivery、搜索投影和版本知识 |
| 知识阅读层 | `apps/web/src/views/knowledge/` | 安全的正文与引用、结构化字段渐进披露、不可变版本差异；保留完整公开原文，不取得事实发布或科学推断权威 |
| 商业与协作 | `commercial/`、`comparison/`、`monitoring/` | 账本、权益、导出和团队工作流 |
| 前端 | `apps/web/src/workspaces/research/`、`lib/contracts`、`components`、`views` | 导航状态、分域路由、传输和独立功能面板 |
| 档案共有呈现 | `views/dossier/`、`components/DossierActivityTable` | 专业档案直接消费共有组件与 `dossier/types`；通用档案查询页不再作为组件／类型转导出入口，不拥有其他专业页的读取生命周期 |
| 界面语言 | `apps/web/src/lib/i18n/`、`LanguageSwitcher`、`LocaleEffects` | 中文/英文目录、只含语言的浏览器偏好、同源同步和当前 locale 格式化；不拥有业务数据、API 枚举或查询状态 |
| 高级专业查询 | `components/professionalQuery/` | 薄组装入口、单一草稿/目录读取/验证模型、七类领域表单、共享日期/受控字段与纯选项推导；不拥有事实写入或第二套 URL 合同 |
| 部署与工具 | `deploy/`、`services/`、`scripts/release/`、`scripts/`、`runbooks/` | 安装、隔离组件、发布证据、门禁、恢复与运维 |

入口、领域、持久化和适配器各自负责一层。新增规则进入对应领域模块，不能在 UI、路由和 MCP 重复实现。数据流见 [architecture.md](architecture.md)。

通用 `EntityDossierView` 在呈现或修正分节前，必须核对返回档案与请求实体的 ID 和类型；身份不一致只开放显式重试，不展示另一实体的记录，也不据此修改当前深链。`locationModel.specializedResearchView` 为四类专业实体的唯一视图分派，未知类型保留通用档案；`EntityRoute` 在已确认身份、等待现有导航提交时不挂载竞争的通用档案，避免缓存返回导航额外启动通用公司档案和时间线读取。既有 URL、分节映射和专业来源身份警告不变。公司时间线独立核对请求公司身份：错误归属或明确 401/403 时，不将缓存计数、日期和事件交给展示模块；暂时性 503 保留原授权快照并显示错误。`CompanyIntelligence` 的时间线日期只取自该时间线，缺失时明确显示缺失，不借用档案查询时间。服务器 RLS、查询键和来源事实权威不变。

公司双语浏览器用例与新增通用档案身份/缓存返回用例分别占有原有的 30 秒预算，共用 `company-browser-fixture` 的响应控制及同一可访问性检查；不在已覆盖九个分节、完整资产和双语切换的公司用例尾部追加另一条长流程。原始用例、断言、四种视口和单 worker 保留，新增用例由实时清单一起校验，不能用旧清单或旧结果代替。

`EntityDossierHeader` 是通用档案标题、完整别名、服务端覆盖统计和查询时间的唯一呈现模块；父视图先验证返回身份，再传入这些事实，不引入第二条查询。标题样式独立于公司和药物档案，窄屏采用顶部对齐及 20px 标题层级，完整来源名称仍参与正常换行，不使用省略、裁剪或固定行数。共享的身份换行基础规则保留，旧内联标题及旧重复布局声明移除。

通用概览的 `dossierCoverageNoteText` 仅本地化服务端 `entity_dossier.py` 明确定义的三种覆盖提示和分页模板；未知说明、来源警告、临床标题及科学正文保持原文。分页数量按原始数字字符串插入，不将大整数转换成可能丢失精度的 JavaScript 数字。

`researchRouteEntity` 统一选择当前请求 ID 对应的已选实体或已载入元数据，四类专业实体在只有已选记录时仍按原分节映射跳转，不要求第二份元数据缓存。错误 ID 的元数据在读取第二份档案前明确报错；路由反馈归属小型 `entityRoute` 双语目录，不翻译实体名称或上游错误原文。

`RegistrationForm`、`AccountInvitationPanel`、`OrganizationPanel` 和 `SessionBoundary` 分别拥有注册交互、管理员邀请管理、邀请确认/组织切换和共享会话生命周期；两套工作台消费同一身份上下文和退出动作。每个账号/组织/角色使用独立的工作台 query client，旧上下文的延迟回调不能污染新缓存。表格偏好从 `SessionIdentityContext` 读取身份，不能依赖领域缓存猜测账号。注册与邀请通过生成的 OpenAPI client 调用 `accounts/` 服务。

`components/table/` 分离排序草稿与菜单、列菜单及偏好提交生命周期；
`VirtualDataTable` 组合这些单一实现并保留原有虚拟窗口与行高。
偏好提交捕获账号/组织会话代次、表格键、query client 和不可变载荷，
排队后才开始的请求及版本冲突重试都重新确认上下文。整个逻辑提交复用
原会话写入计数，正常同身份刷新保留一次有界重试；切换、暂停或卸载后
迟到的响应不能写入新缓存。重置成功只在页面和排序意图仍有效时恢复
默认排序，保留等待期间的新排序及未应用草稿。排序仍归属 URL/查询，
展示偏好仍归属服务端，语言切换不触发新的保存。
若结果加载替换了表格，但同一会话中的旧写入已经抵达服务器，只使捕获的
精确活动偏好查询失效并重读；不重放写入或把旧快照直接塞入新页面。

研究阅读版面仍由 `data-surfaces.css` 与 `research.css` 共用规则拥有：排序表头保留词表原大小写并按完整单词换行，`components/table/columnLayout` 为窄排序列保留 120px 最小轨道，不加宽原动作列或选择槽；较宽数据列仍保留既有最小尺寸，整表与各行共用同一轨道计算。数据列仍可横向滚动，不改虚拟窗口、68/46 行高或原始字段。次要筛选项自然顶端对齐，日期组不能拉伸相邻单行控件。`PublicResearchPanel` 的标题、说明和可见展开状态分轨呈现；仍沿用原披露与显式查询链路，不因版面或语言变化提交草稿、自动查询公开来源或写入事实。

`views/account/` 唯一拥有资料/密码草稿、校验、捕获提交与反馈；`OverviewView` 只组合身份与两份短表单。`components/identity/useIdentityOperation` 统一同步锁和挂载生命周期，不把密码或邀请码放入通用 Mutation 历史；成员目录、确认草稿与读取对账归属 `useOrganizationMembership`，旧内联邀请 Mutation 已退出。`useSessionWritePending` 只订阅既有 `organizationSession` 写入计数；退出和组织切换仍由 `SessionBoundary` 最终执行，不引入第二套授权或传输合同。邀请受理后读取失败只允许重读目录，不重发邀请码。

`contracts/session.loadSession` 统一拥有身份配置与当前账号读取的请求生命周期：并行读取、10 秒整体上限、失败即取消同组请求，并在退出或取消时释放定时器和监听器。只有身份配置有效且当前账号明确返回 401，才进入未登录状态；超时、配置错误或其他身份错误不开放工作台。初始会话验证不叠加普通查询的自动重试，错误页提供显式重试；组织重新确认也调用同一有界读取链路，不使用兜底身份。

ORM 的公共入口是 `models/__init__.py`，只聚合显式导出；领域表分别属于账号、组织配置、实体主数据、药物管线、临床、化学、入库、治理、检索投影及商业领域。`models/base.py` 单独拥有 SQLAlchemy registry、时间戳和 UUID；`models/enums.py` 拥有共享枚举。领域模块不导入聚合入口，避免反向依赖与重复映射。多组织迁移单独增加 `OrganizationMembership` 权限权威并保留全局身份与原业务归属，不能继续从 `User` 读取组织角色。

企业管理的查询键按概况、用户、用户组、访问治理、模型与审计划分，按活动功能加载。`views/enterprise/` 拥有各功能面板及操作表单，`FeatureQuery` 负责加载和失败反馈；权限复查失败不继续显示旧管理数据，也不把失败伪装成空列表。`useEnterpriseOperationBoundary` 统一同步锁与操作对账，不将凭据放入通用 Mutation 历史；`useEnterpriseCommands` 提交前读取同一查询缓存的当前状态、目标身份与已声明版本，不改写捕获意图、不替代服务端授权。`components/accountInvitations/` 的状态所有者由工作台组装，面板与一次性代码弹窗仅呈现；没有第二条邀请提交链路。`ModelsPanel` 与 `LLMProviderModal` 分别拥有列表和配置，旧内联弹窗已移除。审计的筛选/查询仍由主视图拥有，面板保留输入、错误恢复和匹配查询的正常缓存，不显示另一组条件的旧事件。平台面板已移至唯一 `views/environment/PlatformPanel.tsx`，不在企业页保留竞争入口。环境模块的网关版本、主机报告、安装配方、CLI 执行和平台证据分别有独立职责；只有受控本地主机可以明确执行安装，Web 不执行命令。源码/安全/部署连接见 [环境管理](environment-management.md)。

## 本次整理

证据查证使用独立的双语目录；`evidencePresentation` 仅格式化界面定位标签和安全来源链接，`EvidenceRecord` 拥有原文预览/展开与引用卡片。旧视图内联呈现已退出。证据域名、归属说明、文档名、引文内容、URL 与坐标值始终保留来源原值；界面语言切换不提交查询、不改写草稿、当前定位或研究 URL。原真实引证连续性用例增加语言验证，独立受控用例验证英文初访、中文持久化及原文保持，均不替代真实授权检索。

公开来源表单的窄屏行由 `public-research-query` 单独拥有：关键词、范围和操作各占完整一行，沿用原输入状态、明确提交和隐私边界，不修改其他情报查询表单。专利范围的英文标签明确为历史著录元数据，主题值与来源语义不变。原专利用例同时验证中英文展开表单的触控高度、完整行宽、操作文案与无障碍；其他来源消费者由真实只读页面补充检查。

阶段清单与文件分配参数保存在运行器独立拥有的目录，不能放入 Playwright 会在开跑前重建的输出目录。该状态在用例结果、原有质量报告与阶段清单的校验完成前保留；缺少清单仍然失败，不能从测试总数或旧结果推断覆盖。

浏览器证据写入前检查目标文件与原子不覆盖能力；不支持该能力的挂载文件系统明确失败，不自动换成覆盖或非原子写入。本机证据应使用位于 E 盘 WSL 存储中的原生目录，再将已验身份的交付副本导出到 E 盘 Windows 目录。

CI 仍保留原六项作业及 15/45 分钟、单 worker、四种浏览器项目和全部性能/视觉/权限/协议门槛。`scripts/browser_cases` 与 `browser_phases` 唯一拥有实时发现的用例身份与明确分配；八个已验证不依赖真实后端的界面文件由现有前端作业在原构建与真实账号检查之后执行。公司双语文件另由新增的 `company-controlled` 作业在同样的 15 分钟上限内执行，既不挤占前端原预算，也不重复占用完整栈的串行预算。`run_controlled_browser_acceptance` 只启动已构建的前端，保留一个不监听的后端端口并沿用既有字体/Chrome 验证；两类隔离作业均保留原 300 秒执行上限。v2 清单与 `browser_phase_cli` 必须证明三份同源码、同清单、同浏览器结果无漏测、重复、跳过、重试或失败，才汇总完整证据；任意第三份证据缺失也不能发布完整结果。数据库、真实权限、Web/MCP 同事实、双客户端和原有计费负载仍属于完整栈。普通本地命令与基线复查默认保留完整集合，不通过修改默认 Playwright 排除规则来分配测试；划分不改变原始测试集合。

`schemas/__init__.py` 是唯一公共契约入口；输入校验和响应模型按账号、企业、实体、管线、临床、专利、交易、治理、来源和商业领域定义。领域契约只从具体依赖模块导入，不反向依赖聚合入口。公共查询元数据和排序类型独立，跨领域档案聚合只向具体领域契约依赖；OpenAPI 漂移门禁验证重构不意外改动客户端协议。

`http/` 拥有分域 transport；账号、组织、注册、企业人员/组、API 密钥与模型配置各自拥有路由，公共查询校验在 `query_contracts.py`，HTTP 配置绑定在 `runtime.py`。模块不得反向导入 `api.py`；应用入口只负责组合它们。持久化、领域契约和 HTTP 模块的依赖环及反向引用由 `test_architecture_boundaries.py` 约束。账号与组织的保留式迁移、会话及回退边界见 [accounts-and-organizations.md](accounts-and-organizations.md)。

`intelligence/context.py` 拥有请求级 Session、组织、发布可见性与有界身份缓存；各领域 SQL、身份谓词、facet、信号和格局聚合通过显式函数依赖组合。`intelligence/service.py` 只保留 48 个公共方法的类型签名与委派，不拥有第二套 SQL、动态转发或 mixin。跨领域档案只调用具体查询模块，领域不得反向依赖门面。

接入控制写入由 `ingest/commands/` 负责事务、状态冲突、幂等、审计和精确 Temporal execution；它不导入 FastAPI、HTTP 或应用入口。传输层保留原 HTTP 状态和响应契约，将命令错误统一映射，不能另写一套取消、重放或隔离转换。

研究入口只组装 `SessionBoundary` 与工作台。`useResearchNavigation` 管理稳定 URL、返回路径、实体解析、浏览器历史和非紧急导航；`savedSearchLocation` 是可单测的保存检索恢复模型；19 个领域 Route 拥有具体视图的 props 和懒加载。商业界面的状态/操作与表格、生命周期、风险、账单及确认表单在 `views/commercial/` 按职责分开。

`ProfessionalQueryBuilder` 只选择活动领域并显示统一的查询摘要；
`professionalQuery/useProfessionalQueryModel` 是唯一草稿、目录请求、验证与执行所有者。
各领域字段使用精确 `Pick` 类型消费模型；管线临床/交易信号单独呈现，
相关依赖字段的清理仍复用原更新规则。`options/` 按领域提供纯目录/条件计数
推导，不请求网络、创建状态或更改 API 值。共享日期与受控 facet 只负责交互，
无来源选项仍按原规则不呈现，无权/失败不伪装为可用。原 1,747 行组件中的
字段、目录与草稿实现已移出，未保留竞争副本；拆分本身不宣称英文正文已完成。

`EntityCandidateInput` 是单选与多选筛选的唯一候选检索、键盘消歧、防抖及失败恢复实现。草稿关键词变化时旧候选立即不可选，未解析的词不能意外提交外层表单；候选错误明确重试并恢复输入焦点，首次 Escape 只关闭候选。单选/多选包装只拥有已选稳定 ID、类型与身份核对、读取恢复和选择上限，不再复制检索与键盘逻辑。全局检索执行筛选、排序或分页保留当前列表/格局及分析展示模式，展示变化不另建查询权威。

`useFilterDraft` 按已执行条件的内容管理管线、新闻、交易与监管的本地输入：等价的父对象重建、结果刷新和展示切换保留未提交草稿；恢复真正不同的 URL 条件则在同次渲染重置。旧查询遗留的异步更新不能覆盖新查询。草稿不直接驱动结果请求，提交后的 URL 条件仍是查询、分页、保存检索和分享链接的唯一权威。

`useSearchFilterDraft` 在同一实现上声明由结果表管理的排序字段；仅改变排序时
同步这几个字段并保留尚未提交的检索条件，真正改变已执行条件仍重置草稿。
交易、管线、监管、新闻和流行病学共用该规则；专利页的排序本已与筛选草稿分离。

`EntitySearchInput` 只负责可选的名称联想，不替代稳定实体 ID 筛选。未明确用方向键选择候选时，Enter 执行输入的原词；新词、短词、请求失败和刷新中的旧联想均不可选。其请求、键盘与失效恢复只在该模块实现，研究视图不再保留旧联想分支。保存基础检索同样采用已执行条件，而非尚未提交的输入；结果快照由 React Query 直接拥有，不再叠加第二层延迟结果状态。

`workspaceRouting.researchReturnLocation` 是研究返回上下文的唯一校验入口：只接受研究工作台内的已知视图、有效档案标识以及最长 4096 字符、最多三层的上下文。外部地址、内部管理页、控制字符、路径变形、重复视图和无效标识拒绝；解析嵌套前先剥离原始 `from`，避免无界递归。检索、完整档案和跨领域链接共用该契约，保留筛选、排序、分页、展示、档案分节和原预览选择；不依赖未知浏览器历史或外部 referrer。

`lib/workspaceRouting.ts` 是稳定公共入口及有界来源校验，不再混装所有领域的类型、枚举、参数解析和序列化。`lib/workspace/types` 拥有位置契约，`catalog` 拥有工作台、分节、权限及参数白名单，`queryValues` 拥有数值/日期/标识/排序规范化，`queryParser` 与 `querySerializer` 分别读写 URL。两者显式接收公共入口提供的来源规范化函数，不反向导入入口，不复制来源安全规则；领域消费者继续只依赖公共入口，内部模块保持无循环。

`ResearchReturnControl` 在工作台的懒加载和档案查询边界之外，统一呈现已校验的来源返回：药物、靶点、临床与其他领域在加载、无效类型或请求失败时仍可返回，不等待档案正文或目标名称。领域页不再接收或实现第二套来源返回 props；靶点竞品管线使用同一来源标签。临床详情仅在没有跨页来源时显示本页“返回试验列表”，保留当前临床查询且不与跨页返回竞争。

`useRouteEntity` 统一拥有路由实体读取及跨页面恢复，保持同一实体查询键和身份隔离缓存。明确切换页面或选中实体时，已失败且空闲的读取可以重新请求一次；成功缓存继续复用，普通重渲染和再次失败不触发重试循环。返回同一靶点的预览不再被档案页的失败缓存阻断。

实体快速预览通过 React Portal 放在页面根部，与主内容的定位、层叠和横向滚动隔离，仍使用共享模态焦点栈。长名称的靶点直达摘要和抽屉动作可换行；移动端不靠强制点击穿过背景内容。外部检索仍只展示已发布记录，测试数据必须满足这一边界，不能用开放 draft 查询来修复夹具。

`EntityPreviewDrawer` 单独拥有快速预览的呈现、状态与模态焦点生命周期；检索页只提供当前实体和导航回调，不在内部再放一份抽屉实现。`entityPresentation` 为检索行和预览共用类型名称、匹配解释及公开标识去重，继续调用 `publicEntity` 的公开字段边界，不能展示内部来源或治理标识。关闭预览仍由检索页唯一更新本地选择及 URL。

`TargetView` 只组合靶点档案查询、标题、分节和同一来源证据抽屉。`views/target/` 分别拥有概览、关系与转化证据、分子活性/SAR/结构及相关领域记录；不会在主视图保留第二份领域表格。`TargetDossierHeader` 单独呈现名称、UniProt 和三项真实统计，完整基因标识及来源别名在原生可展开区域保留；查询时间始终可见，并明确不等于所有来源最后更新时间。展开状态只属于当前靶点的展示，语言切换不重载档案或关闭已展开别名，不产生第二条数据查询链路。靶点竞品管线的查询、受控输入同步、防抖、分面缓存、分页、分析、列设置和选择由 `pipeline/useTargetPipeline` 唯一管理；主/高级筛选、工具栏及药物/项目结果表仅消费有类型的状态和回调，不再自行读取 API 或创建竞争状态。展示标签和筛选摘要归属 `pipeline/presentation`，完整来源事实、原始查询键、可比性与服务端全命中集统计保持不变。模块依赖、查询与辅助规则的唯一归属有定向回归，领域模块不得反向导入 `TargetView`。

靶点竞品管线首屏仅保留搜索、药物类型、最高阶段、项目状态及排序五项控制。适应症领域、地区和临床/交易信号由 `PipelineSecondaryFilters` 在原有单一高级展开区呈现；对应条件计入同一激活数，保存或深链条件自动展开，清空后不强制折叠。布尔值 `false`、零命中已选项、临床评价及交易币种/金额依赖清理规则保持原契约；主、高级与次级呈现模块均不自行查询或创建状态。

`TargetView` 只为靶点类型发起档案查询，并在挂载标题、竞品管线和其他子模块之前，核对档案实体及其中 profile 实体都与请求靶点的 ID、类型一致。任一不匹配均显示当前语言的错误与显式重试，不呈现另一实体的数据、不启动下游查询、不更改原分节。重试仍调用原查询的 refetch；不新增查询键、缓存或自动重试。该客户端一致性边界不能代替服务端权限和数据治理。

`views/drug/DrugDossierHeader` 只呈现已有药物档案：完整名称和摘要、最高阶段、项目数与靶点/适应症数保留在首屏；全球/中国阶段、机构数、最新状态日期及完整来源别名放入原生可展开区域。六项原始统计仍完整保留，不用查询时间替代缺失状态日期，也不翻译未知来源阶段。展开状态限于当前药物，语言或分节切换不关闭已展开别名，不额外读取 API；查询、分页、来源抽屉和权限仍归属原 `DrugView` 与领域模块。原六列指标网格及旧内联页头已经退出，不保留竞争呈现路径。

治理服务的公共入口为 `governance/service.py`，不重复定义辅助规则。`contracts` 拥有异常、结构化治理版本和分段类型；`citations` 拥有分段、引用定位和去重；`fact_identity` 拥有稳定事实键及载荷身份；`temporal_merge` 拥有阶段、日期和历史合并；`source_profiles` 拥有来源裁剪和权威身份校验；`policy` 与 `model_audit` 分别拥有策略指纹、预算计量和审计内容。源资料、策略指纹、字段规则与公开异常接口保持不变；这些模块不能反向导入治理编排服务。

已批准结构化事实通过 `governance/materialization` 的唯一分派进入按职责分开的 `materialize_*` 领域模块。`MaterializationContext` 显式声明现有事务、组织、规范化器及授权实体/关系/来源类型能力；各模块不自行创建治理服务、会话或另起提交边界。服务不保留旧的领域材料化方法，投影失败和延后语义仍交给原发布流程处理。

ClinicalTrials.gov、NextPharma 与 ChEMBL 的确定性处理分别归属 `adapter_clinicaltrials`、`adapter_nextpharma` 和 `adapter_chembl`。`AdapterContext` 显式复用同一来源版本、会话、组织、对象存储、规范化器和统一暂存/失败/状态回调；适配器保留来源授权、不可变内容哈希、幂等策略和审计，不自行构造另一套治理服务。`govern_version` 只负责选择已识别来源及受控模型处理。

官方来源的连接器、检查点与注册分别属于 `ingest/clinicaltrials.py`、`public_sync.py`/两个 `*_sync.py` 和 `public_sources.py`；`public_http.py` 复用唯一有界读取器统一官方接口的流式响应上限。CLI 只委派，旧内联连接器/重复注册实现已移除。`source_routing` 统一规范配置比较，`governance/source_policy` 统一来源策略身份，`source_updates` 只负责同记录的有锁版本推进。前端来源编辑、参数合同/字段与同步状态位于 `views/dataFactory/`，主视图不再拥有重复来源表单。完整行为见 [自动公开来源入库](automatic-public-source-ingestion.md)。

数据工厂的隔离处置、源对象/版本、版本重放、运行重放/取消、阶段状态与校验发现各归属 `views/dataFactory/` 的六个小模块；`DataFactoryView` 只组装原查询与命令回调，不保留第二份内联弹窗。共享 `useModalFocus` 拥有可见焦点、可嵌套背景隔离与关闭恢复，`useDismissibleDetails` 只管理临时原生弹出菜单的退出，不读写业务筛选或草稿。所有业务标签页复用 `ResearchTabList`；可显式关联同一活动面板，不复制键盘状态。`InlineEntityLinks` 呈现完整授权关联集合及数量，临床角色与专利列表消费同一呈现，不裁掉第四条记录，不制造来源或推断科学关系。商业生命周期命令仍归属 `useCommercialWorkspace` 的单一操作/审计链路；呈现层等待其成功结果再关闭或清空，失败/提交状态由当前表单呈现。靶点筛选样式退出企业模块归属靶点，知识网格的滚动边界由知识样式独立拥有。

`scripts/release/` 是发布证据的唯一实现，合同、记录、文件安全、策略、领域校验、采集、签名、打包、验证与交接各自归属具体模块。`release_evidence.py` 仅保留已验证的直接 CLI 与其他命令入口依赖的公共委派。该库纳入 Ruff/Mypy、依赖 DAG 和真实文件/子进程/签名回归，不保留旧 7,000 多行实现。

公共名称集中在后端 `product.py` 与前端 `lib/product.ts`；API、MCP、来源请求、登录和导航复用该定义。`pyproject.toml` 唯一拥有产品版本：每合并一个 PR 到 main，补丁号自动加 1，到 100 向次版本进位，次版本到 10 向主版本进位。计数游标位于同一清单的 `tool.x-pharma.versioning`，自动化流程与恢复规则见 CONTRIBUTING 的 Product version counter；不回溯启用前历史，不按提交数量或机器人元数据提交重复计数。API 与 MCP 读取发行包元数据，Web 构建读取生成 OpenAPI 并校验清单镜像，HTML 生成器读取同一产品清单。版本回归同时检查实际 MCP initialize 协议和页面可见标识，不能把 SDK 版本当产品版本。内部数据库、协议和 CLI 标识保持稳定，已有业务数据不因品牌或产品版本变动而迁移。

原 10,431 行集中样式按职责拆为 16 个模块：基础、登录、导航、共享数据表面、研究、用户中心、靶点、档案、商业、企业、知识、数据工厂、治理、化学、临床和监管。`styles.css` 保持共享及基础领域布局顺序，证据/知识布局与响应式仅由所属视图按需加载 `styles/knowledge.css`；环境、组织与检索起始引导各有局部呈现样式，不拥有查询或权限状态。`design-system.css` 只导入五个主题模块，分别拥有 token、控件、排版、业务表面和第三方适配。所有领域色值已改为语义 token，415 条被主题覆盖的重复声明已删除。设计权威见 [design-system.md](design-system.md)。

`configure-development.py` 生成独立密钥、数据库 URL 和 0600 私有配置，保护已有环境，默认关闭远程 AI。生产凭据仍由部署环境注入。

公开目录包含完整应用、迁移、生成客户端、测试、配置、容器、Kubernetes 和运维源码。私有环境、业务数据、运行证据、缓存、历史快捷链接和一次性空文件保留在原私有环境。

## 已识别的维护风险

`public_research/`按提供者适配只读在线检索，HTTP与共用`PublicResearchPanel/Results`不写事实。`search/related`拥有关联解析，`search/keyword`拥有关键词谓词；靶点profile移入`materialize_profile`，旧分派内联退出。`trial_labels/clinical_semantics`拥有来源名称/关系，`clinical_links/clinical_role_policy`统一登记药物关联与明确角色；历史顺序推断退出查询但保留审计行。`ingest/xml`统一安全XML，`request_body`统一账号/公开请求限制，不保留竞争实现。数据性质见[公开调研](public-research.md)。

大 SQL 查询的复杂度来自同一授权命中集的过滤、身份归并与统计。查询模块继续按谓词、读取、信号和聚合职责演进，不能用动态转发、复制 SQL 或改变命中语义换取更短文件。纯公共方法签名较长不意味着应复制业务实现；边界测试禁止职责回流。

历史 CI 的双入口任务引用了已退出统一拓扑的 `mcp` 和 `search-projector` 服务。验证应使用当前 API/jobs/parser 拓扑、独立配置和真实夹具，同时保留既有门禁。

恢复镜像与新源码是不同候选。每个候选的源码摘要、测试、镜像和实际验收须绑定同一身份；恢复时的成功结果不计为新代码部署证据。

商业概况的客户端、待执行导出、账单死信和处理中争议计数在服务器统计完整组织范围，不从最多100/200条的独立面板列表推断。客户端、账单、争议、导出、风险和生命周期按当前面板加载、独立失败/重试；概况失败不会撤掉其他面板的导航。账单面板的账户与投递是同一功能的两个明确请求，不再用跨六个功能的聚合阻断整个工作台。

浏览器验收保留原场景标签和四视口矩阵，并增加一条研发导航、五类档案、筛选草稿与环境控制注册；其两个新标签同时加入完整覆盖合同，不能在没有执行时宣称环境已验收。`e2e/workspace/` 按场景拥有实现，最长的全程验收拆成17个显式、有类型的连续步骤；步骤上下文由前一步的返回类型派生。`workspace.spec.ts` 只注册测试，公共 helper 不注册第二套场景；像素、性能、超时与完整覆盖门禁保持不变。

共享整栈的 CI 浏览器质量测量显式使用一个 worker，以减少不同页面的加载与密集操作互相干扰；四个视口和全部 140 场景仍执行，既有动作/用例超时、INP/LCP/CLS、像素与初始资源门槛不变。标准验收脚本仍支持 1–16 worker，默认 4；收费 MCP 的 20 请求/4 并发和 p95 门禁、账号/邀请及数据库并发检查独立保留。串行配置本身不证明通过，质量结论仍须读取对应提交的实际结果。

虚拟表格使用原有虚拟器、有限可见窗口、行高和画布总高；首个可见行偏移归属 tbody 顶部占位，行在顺序流中排布。旧逐行绝对定位和 `translateY` 已移除，不保留备用产品渲染。结果表的视觉与性能核验归属唯一 `dense-results-visual` 步骤，其两个布局模块分别检查固定列（含宽屏无溢出）及纵向有界窗口，并在 finally 恢复原滚动位置。真实顺序流候选在定向表格路径和正式十项平板前置组合中产生同一 SHA-256 图片，经审阅后仅维护这一张受产品布局变动影响的平板参考；其余十九张保留。清单由原生成逻辑重算，日期不是全站重新截图宣称。旧参考/隔离/定位实验的失败证据保留，不追逐两个旧绘制相位，不放宽门槛。之前四视口主流程定向 16/16 缺少前置两项正式无障碍审计，不等价于完整验收。原掩码、0.001 像素容差、资源/性能和动作门禁不变；正式结论必须读取当前提交的实际结果。CI 任务默认调度空间为 45 分钟，原动作/用例时限及全部 SLO 不变。

逐次参考审阅记录见 `visual-baseline-reviews.md`；清单只记录资产身份，不把历史生成日期当作所有资产刚刚重新截图的证据。

浏览器查找和版本输出由 `scripts/lib/browser_runtime.sh` 单独拥有，普通运行在 Docker/夹具之前调用。CI 安装客户端后先运行同一 `scripts.browser_visual_profile`，使用参考清单的同一安全元数据读取器；Chrome 小版本漂移给出明确错误，不自动改参考、不降级浏览器、不放宽容差。Edge 对比、显式 Chrome 审阅和显式中断夹具恢复保留原各自边界。

把固定 mirror list 的 Azure Ubuntu 传输地址改为 Ubuntu 官方 HTTPS archive。

普通浏览器验收只按本次运行生成的邮箱前缀清理账号及其关联记录，不清理其他运行或相似名称的账号。只有显式 `--recover-interrupted-run` 才进入历史测试账号恢复模式；实体仍按已登记的夹具标识清理，原用户和业务数据不属于验收清理范围。

浏览器验收和中断恢复都必须以 `PHARMA_BROWSER_TENANT_SLUG` 明确绑定活跃测试组织。未设置、空值或非法值在任何运行环境准备前失败；指定组织缺失或停用也直接失败，不回退到第一个组织。复用有真实数据的本地栈时，先通过现有 bootstrap 创建无数据、无 API key 的独立验收组织；CI 显式使用其已 bootstrap 的 `e2e` 组织。临时身份、来源和事实仍由同一夹具生命周期清理，不复制验收实现。
