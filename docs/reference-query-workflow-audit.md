# 专业医药数据库查询工作流对标审计

## 1. 范围与边界

本审计于 2026-07-23 至 2026-07-30 基于用户已授权登录的医药魔方 NextPharma 公开可见交互完成，覆盖基础查询、医药交易、临床结果、监管与安全、流行病学、新闻热点六类工作流。审计只记录查询语义、控件类型、状态关系和研究路径，不保存第三方凭据、未授权数据、商标资产、页面源码或像素实现。

### 1.0.17 2026-08-01 化学真实 API 验收收束

此前化学浏览器场景真实操作 Ketcher 与浏览器 RDKit，但业务检索响应仍由路由 mock 提供，不能证明人员入口连接 PostgreSQL/RDKit 权威事实。v1.9.68 删除该 mock，以运行隔离结构记录执行真实登录和 `POST /api/v1/chemistry/search`，逐项核对 exact 模式、规范化结构、实体 UUID、名称、InChIKey 与页面描绘；四视口 `116/116`，`chemistry_real_api=true`，并显式证明临时结构记录清零。

这关闭的是受控人员入口到化学数据库的真实性缺口，不是正式规模验收。批准语料相关性、并发、容量、HA/PITR 和专业药化 UAT 仍缺失，因此 D-09 保持未关闭。

### 1.0.16 2026-08-01 化学编辑器冷路径收束

本批未新增参考产品提交证据，而是继续关闭本平台自身可复现的性能缺口。v1.9.66 已阻止 Ketcher/RDKit 进入整个工作台首屏，但进入结构检索页面后默认绘制标签仍立即挂载编辑器，用户即使只使用高级 SMILES/SMARTS 输入也必须承担大型编辑器和 WASM 初始化成本。

v1.9.67 保留完整绘制结构入口和画板能力，将编辑器动态 import 移到明确激活动作之后。真实 Chrome 四视口先证明结构检索冷路径没有专业编辑器资源，再打开画板、观察 `StructureEditor` 动态 chunk、操作 Ketcher 苯环、应用结构并完成 RDKit 描绘；最终全量 `116/116`。该优化不改变化学查询 API、结构格式或服务端事实，不通过删除编辑功能降低成本。

该证据仍不证明正式化学数据规模下的相关性、并发、容量、目标网络加载时间或专业药化用户 UAT，D-09 和生产性能门禁保持未关闭。

### 1.0.15 2026-08-01 首屏资源边界收束

本批未新增参考产品页面提交证据，而是关闭本平台可复现的性能门禁缺口：现有构建只证明专业视图和结构编辑器使用动态 import，不能阻止共享依赖、Ketcher/RDKit 或大型图表在未来改动中被静态 import 拉回首屏，也没有约束完整静态闭包体积。

v1.9.66 从生产 manifest 递归计算两个工作台入口的静态 JS/CSS 闭包，限制原始和 gzip 体积，并禁止结构编辑器、RDKit、Ketcher及大型图表进入首屏；化学工作台仍真实加载编辑器、RDKit 和相应 WASM。Google Chrome 四视口登录首屏进一步通过 Resource Timing 证明未提前加载这些专业资源，随后原有化学场景仍验证按需结构能力可用；`116/116` 通过且临时数据清零。

该证据只关闭本地首屏包体无界和专业资源误预加载风险，不代表目标环境网络、真实用户 P75、并发负载、长稳或参考产品性能对比已获批，因此 `performance_and_visual_regression` 保持 `partial`。

### 1.0.14 2026-08-01 八域错误与权限恢复矩阵

v1.9.63 已实现八域统一状态组件，但浏览器证据只覆盖真实 API 延迟、取消和恢复；组件测试中的 `503/403` 不能单独证明八个专业页面都正确连接同一合同。v1.9.64 将错误与权限恢复拆成独立四视口场景，避免继续扩大原本已经很长的主研究链。

每个域先以受治理夹具和稳定 URL 获取真实命中结果。故障处理器随后对每次目标请求先执行真实 API 并断言上游 `200`，再在浏览器传输边界注入三次 `503` 或一次 `403`：前者必须耗尽既有有界重试、保留旧结果并恢复真实 API；后者必须立即隐藏结果并重新校验真实 API。Google Chrome 四视口各 `29/29`、合计 `116/116`，新增 `professional_error_permission_matrix=true`，视觉基线未更新，临时数据清零。

受控注入不是生产网络故障、企业 IdP、真实角色/字段授权或业务签字证据。正式数据和真实授权策略下的逐任务矩阵、人工辅助技术、操作系统缩放和专业用户 UAT 仍须完成，C-07 保持未关闭。

### 1.0.13 2026-07-31 八域查询状态连续性

v1.9.62 已证明全局实体查询可中断，但八个专业域仍在刷新已有数据时用全页加载态替换结果，瞬态失败也会隐藏上次成功结果；`isPending` 还可能把未执行的空闲查询误报成取消。该差异会破坏组合筛选后的研究上下文，属于本平台自身可复现缺口，不需要复制参考页面或引入新查询后端。

v1.9.63 将八域统一到一个显式生命周期：首次加载可取消；后台刷新保留结果；取消刷新保留筛选和结果；瞬态失败标记部分可用并允许恢复；403 立即隐藏缓存结果；空闲、空结果和取消互不混淆。每个域的刷新仍通过同一服务端查询、稳定 URL、query key 和 AbortSignal，不增加客户端事实或第二套筛选语义。真实 Chrome 四视口对 `/api/v1/entities`、`/api/v1/pipelines`、`/api/v1/trials`、`/api/v1/patent-families`、`/api/v1/deal-transactions`、`/api/v1/regulatory-event-timeline`、`/api/v1/epidemiology-observations` 和 `/api/v1/news-events` 逐一先获得真实 `200`，仅延迟浏览器交付，再验证旧结果可见、取消、保留和真实重试；`112/112` 通过，视觉基线未更新，临时数据清零。

该批关闭八域自动化刷新/取消连续性缺口，但没有把受控延迟注入冒充生产网络故障、正式权限组合或业务签字。正式数据上的逐任务错误/权限矩阵、人工辅助技术、操作系统缩放和专业用户 UAT 仍须完成，C-07 保持未关闭。

### 1.0.12 2026-07-31 专业查询取消与恢复收束

本平台八个专业查询此前已经把 TanStack Query 的 AbortSignal 传到生成客户端和真实 fetch，但页面只显示不可操作的加载状态。用户在高延迟组合查询中只能等待、换页或刷新；现有 `[workspace-states]` Playwright 场景还通过静态路由响应模拟加载和错误，不能证明真实数据请求可取消。该差异属于现有查询工作流的恢复性缺口，不需要复制参考产品页面或引入第二套查询协议。

v1.9.62 为全局实体、管线、临床、专利、交易、监管、流行病学和新闻查询增加统一“取消查询”入口。操作按当前完整查询键调用 React Query cancellation，底层生成客户端终止同一 AbortController；初次请求取消后显示明确状态，筛选仍由稳定 URL 持有，“重新查询”执行原查询。组件回归使用真实 AbortSignal 锁定中断和恢复；真实 Chrome 四视口先让 205 条 PostgreSQL 记录经 OpenSearch 与 `/api/v1/entities` 返回 `200`，仅延迟浏览器交付，再取消、核对终态、解除延迟并重新获得完整结果。报告 `112/112`，视觉基线未更新且临时数据清零。

该批只证明本平台受控真实链路中的查询取消与恢复，不把网络延迟注入当作生产故障证明，也不替代八域逐任务错误/权限状态、人工辅助技术、正式数据和专业用户 UAT；C-07 继续保持未关闭。

### 1.0.11 2026-07-30 交易全局组合查询收束

### 1.0.10 2026-07-30 专利全局组合查询收束

同一已应用 `EGFR` 查询切换到可视化后，页面继续保留查询总量和订阅/导出上下文，并按研发阶段、靶点、适应症、靶点组合、研发机构和 Modality 提供图示/列表分析；聚合维度还可区分全球、中国、美国、欧洲和日本的最高阶段或机构地区口径，并展示数据来源。由此形成强制对齐规则：结果表和统计分析必须由同一服务端查询状态驱动，聚合具有口径、来源与时点，不能用首页静态图表或当前页前端汇总代替。

## 2. 查询语法模型

这些工作流可以归纳为以下组合，而不是一个无限扩张的通用表单：

```text
Query = Entity selectors
      + Domain attributes
      + Lifecycle and time constraints
      + Geography and rights constraints
      + Evidence or event constraints
      + Presentation state
```

| 层级 | 交互语义 | 目标实现规则 |
|---|---|---|
| 实体选择 | 药物、机构、靶点、适应症等使用至少两个字符触发的联想与消歧 | 使用稳定实体 ID 提交，显示名称只作 UI；支持多选、移除和别名命中解释 |
| 领域属性 | 模态、创新类型、药品类别、研究类型、交易类型等领域枚举 | 枚举由版本化领域契约定义，facet 返回当前授权结果数量；禁止前端自造选项 |
| 生命周期与时间 | 阶段、里程碑、发表/交易/终止/更新时间以及预设时间窗和自定义范围 | 预设时间窗必须转换为明确的闭区间/开区间并进入 URL；全球与中国口径分别建模 |
| 地域与权益 | 机构所在地、研发地区、交易流向、权益地区和商业化权益 | 区分地理位置、监管辖区和商业权益，不能共用一个 `geography` 字段 |
| 证据与事件 | 临床结果、总体评价、关键结果、审批类型、交易状态和金额 | 事实存在性与评价值分别筛选；金额必须带币种、口径和归一化规则 |
| 展示状态 | 图示/列表、统计维度、排序、列、密度、分页和导出记录 | 展示偏好不改变事实查询；列显隐、顺序和密度按租户/人员/领域在服务端持久化，分享链接只保存影响结果集的状态 |

## 3. 共享交互原语

1. 实体联想输入在达到最小字符数后触发，候选项应包含实体类型、别名或外部 ID，选择后保存稳定 ID。
2. 高频有限枚举使用单选标签；长尾选项通过“更多”展开，不把所有项永久堆在首屏。
3. 时间条件同时提供“全部、近 1 个月、近半年、近 1 年、自定义”等预设；自定义选择后才展示日期范围。
4. 全局和中国阶段是两套并行口径，阶段值相似但数据含义和起始日期不同。
5. 布尔存在性使用单选或复选，例如有无临床结果、有无交易；存在性不能用空值猜测。
6. 检索与重置是整组查询的明确提交动作；重置必须同时清理 URL、依赖选项和分页游标。
7. 查询下方统计图与结果列表共享同一已应用查询，不应各自维护一套隐藏筛选状态。

## 4. 领域专属逻辑

### 4.1 基础药物与管线

- 核心实体：药物、研发机构、靶点、适应症。
- 项目属性：模态、适应症领域、创新类型、药品类别、专题标签、递送系统、剂型。
- 生命周期：全球最高阶段、中国最高阶段、各自阶段开始日期、里程碑事件与日期、全球研发状态。
- 知识产权：化合物/序列专利到期时间窗。
- 机构与权益：原研机构所在国家/地区、研发权益地区、商业化权益、机构评分和机构类型。
- 证据与商业：审批类型、临床结果存在性、临床结果最优评价、交易存在性和交易金额。

### 4.2 医药交易

- 交易参与方必须显式区分转让方和受让方，同一机构可按角色筛选。
- 时间至少分交易初始时间、终止时间和最新更新时间，不能折叠成一个通用日期。
- 交易分类至少区分业务类型与流向；流向由参与方地域关系派生，但应保存规范枚举。
- 管线交易需要交易时研发阶段与当前最高阶段两个时间切片。
- 权益地区、当前交易状态、参与方类型、参与方所在国家/地区和金额范围是独立条件。
- 公司收并购与管线交易是同一领域下的不同查询模型，不应只换标题复用全部字段。

### 4.3 临床结果

- 试验药品/联用药品、靶点/联用靶点必须建模为有角色的组合关系，而不是关键词拼接。
- 精确标识包括临床登记号、PMID 和试验简称；应优先于模糊全文检索。
- 结果层条件包括发表日期、试验阶段、是否关键结果、总体评价、IIT/IST、疗法线次和会议。
- 药物项目属性仍可参与筛选，但结果评价属于试验结果事实，不能写回药物主数据。
- 同一个试验可有多个结果版本、会议披露和文献，筛选必须明确结果时点与来源。

### 4.4 流行病学

- 该领域刻意保持较小的筛选面：患者人群、疾病、靶点、地区和统计维度。
- 患者人群是可搜索的规范概念，不等同于疾病名称。
- 统计维度至少区分新发病例、死亡病例和患者总数；每条结果还必须带单位、时间范围和口径说明。
- 地区筛选是结果口径，不应与来源所在地混淆。
- 当前组合条件使用 `epidemiology_search@1` 保存并订阅，保留规范疾病/患者人群 ID、统计口径、时间和排序；消费者复用权威流行病学筛选语义匹配疾病、发布方及患者人群关联疾病/靶点变化，监控中心完整恢复规范 URL。

### 4.5 监管、标签与安全

- 监管机构、辖区、事件类型和事件状态属于事件口径，认定资格、标签变更和安全信号属于不同受控维度，不能压入一个自由文本详情字段。
- 标签必须保留版本、生效时间、批准人群、生物标志物、治疗线次、给药途径、剂型和黑框警告状态；缺失值保持未披露。
- 安全信号必须区分信号类型、医学术语、严重程度、处置状态、识别/确认/解决时间、影响人群和风险措施。
- 并排比较只能使用稳定监管事件 ID 和同一权威查询结果，不能从页面摘要拼接或推断未发布事实。
- 当前组合条件使用 `regulatory_search@1` 完整保存并可直接订阅。消费者复用同一监管领域筛选语义匹配药物、适应症、机构和靶点关联资产变化，监控中心逐字段恢复 URL；排序不构成全库订阅条件，`false` 黑框警告则是明确有效条件。

### 4.6 新闻与会议

- 事件类型、发布方、语言、会议或期刊、发布日期与研究内容范围是独立条件；研究时间线只接受论文、会议摘要、海报和会议演示等受控研发事件类型。
- 当前组合条件使用 `news_search@1` 保存并订阅，保留列表/时间线展示和排序状态；消费者复用权威新闻筛选语义匹配发布方和关联药物、靶点、疾病或机构变化，监控中心逐字段恢复规范 URL。

## 6. 目标查询契约

领域 API 继续独立演进，但所有查询响应统一提供以下元数据：

- `query_schema_version`：解释请求字段语义的不可变版本。
- `applied_filters`：服务端规范化后的有效条件，不回显被忽略的未知字段。
- `facets`：基于当前授权、治理状态和已应用条件计算的可选值及数量。
- `as_of`、`coverage`、`warnings`：明确数据时点、授权覆盖和缺口。
- 稳定游标或有界 offset、limit；任何筛选变化均重置分页。

前端使用共享的 `FilterGroup`、实体选择器、枚举标签、时间窗、日期范围和已应用条件组件，但领域字段、依赖关系和验证规则由各领域 TypeScript/Python 契约定义。不得从任意服务端 JSON 动态渲染未审查控件，也不得把领域业务语义写进通用 UI 组件。

5. 任意筛选变化后分页归零，刷新与前进/后退不丢失条件，重置后 URL 无残留参数。
6. 图示和列表展示同一查询摘要；无权限字段不出现在 facet、列管理、导出或 MCP 结果中。
7. 监管查询选择认定资格、标签变更、黑框警告和安全信号后，服务端返回同一组 `applied_filters`；选择真实事件进入最多四项对比，详情和对比 URL 刷新后保持不变。

10. 全局管线专业查询从权威 facet 目录同时选择两个 Modality 和两个项目标签；空草稿不误报已选条件，加载/空/失败可恢复，提交后四个重复参数完整进入稳定 URL、真实 `/api/v1/pipelines` 请求和领域页恢复。

12. 全局管线专业查询从同一权威 facet 目录选择项目状态、机构角色、机构类型和机构所在地区；本地化标签保持规范值不变，四个条件完整进入稳定 URL、真实 `/api/v1/pipelines` 请求和刷新恢复。
13. 全局管线专业查询从同一权威 facet 目录选择临床结果存在性/评价和交易存在性/币种，并以有界金额范围补充交易信号；六个值完整进入稳定 URL 与真实 `/api/v1/pipelines`，与管线专业页共用互斥和金额校验，不复制关联查询。
