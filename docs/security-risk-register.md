# 镜像漏洞风险登记

本文件记录当前候选版本中没有上游修复的 High/Critical 漏洞及发布决策边界。它不是风险接受批准，也不能替代安全负责人、业务负责人和运维负责人的签字。

## 当前状态

| 项目 | 状态 |
|---|---|
| 技术扫描 | 通过：有上游修复的 High/Critical 为 0 |
| 完整漏洞库存 | 已生成并保存在版本安全证据包 |
| 正式风险接受 | **待批准** |
| Production 发布 | **阻断**，直到取得外部审批引用 |
| Pilot 使用 | 仅限受控网络、受控用户、非公开数据和人工值守 |

候选镜像摘要、源码树摘要、扫描器版本、漏洞库版本和逐项发现只以本次
`scripts/run-security-gates.sh` 生成的仓库外安全证据目录为准。手写文档不得
固化本机镜像摘要或历史扫描计数，因为任一依赖、基础镜像、漏洞库或源码
变化都会使这些值失效。

## 扫描结果

每次扫描都生成源码、API 镜像、PostgreSQL/RDKit 镜像和 OCR 镜像的 SBOM，以及完整
Grype JSON、VEX 后结果和门禁摘要。正式审批必须从该候选证据中逐项核对：

- package、版本、CVE、严重度、供应商修复版本和发行版状态；
- 受影响代码是否在运行镜像中可达，以及当前网络和权限暴露面；
- VEX 是否精确绑定 package + CVE，并附有可复现的不受影响依据；
- 风险接受是否绑定当前镜像摘要、有失效日期并由授权角色签署。

通用 NVD、发行版安全跟踪器和镜像扫描器可能给出不同处置。审批必须审查
当前候选的原始机器报告，不能复用上一个候选的 CVE 列表或只依据单一扫描器
等级。

## 当前控制

- API、worker、search projector、MCP 和测试镜像均使用非 root 用户；运行容器启用只读根文件系统和 `no-new-privileges`。
- PostgreSQL 仅在内部网络暴露，业务数据访问使用非特权 runtime role、强制 RLS 和签名 tenant context。
- 文件和模型输入经过大小、类型、解析、引用和治理门禁；外部输入不直接触发系统命令。
- 可修复 High/Critical 是否存在由当前候选门禁计算；文档不预判基础镜像的实时补丁状态。
- 镜像与扫描器均固定摘要；源码、依赖和三类运行镜像 SBOM 随版本归档。
- 有修复版本的 High/Critical 会由 `scripts/run-security-gates.sh` 自动阻断。

这些控制降低可利用面，但不构成“无风险”或“not affected”的证明。

## 关闭条件

每个未修复 CVE 必须满足以下一种方式：

1. 上游或 Debian 发布修复后更新固定镜像摘要，重建并重新扫描。
2. 形成可复现的不可达/不受影响证据，并以精确 package + CVE OpenVEX 声明记录。
3. 由安全负责人基于威胁模型、暴露面、补偿控制和有效期签署风险接受。

风险接受必须包含负责人、审批单号、适用镜像摘要、到期日期和复审触发条件。不得在仓库中伪造审批单号。

## 发布操作

普通门禁：

```bash
./scripts/run-security-gates.sh
```

Production 候选门禁必须引用真实审批记录：

```bash
./scripts/run-security-gates.sh --release-mode \
  --risk-acceptance-reference SEC-真实审批单号
```

当前没有批准引用，因此本版本只能标记为预生产/受限试点。
