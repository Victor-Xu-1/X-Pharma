# 研发人员视角界面审查

适用产品：X-Pharma，软件版本由 [`pyproject.toml`](../pyproject.toml) 唯一确定并按[贡献规范](../CONTRIBUTING.md#product-version-counter)自动递增。此文记录研发情报界面的信息取舍和改进边界，不是药物效果评价或完整商业验收报告。设计继续采用唯一的简洁白灰设计系统，保留橙色 Logo、账号组织、公开来源和权限边界。

## 信息取舍

- 第一屏回答“研究对象是什么、当前有哪些事实、下一步能做什么”；源码、内部来源 ID 和运行细节不挤占研究结果。
- 保留药物与项目的区别、临床角色、结果评价、日期、许可/来源、证据定位和数据缺失。记录为零不能解释成相关研究不存在。
- 查询响应 `as_of` 是本次查询时间，不是来源更新时间。真实阶段起始、来源发布日期和业务事件日期继续分别呈现，不把它们合并成一个含糊的“最新时间”。
- 常用条件直接可见；次要条件折叠但不卸载输入，已有筛选自动展开。URL、已执行条件、分页、格局、保存检索和未提交草稿的权威保持不变。

## 页面与模块盘点

| 页面/入口 | 发现与处理 | 保留的研发工作流 |
| --- | --- | --- |
| 全局检索 | 简化共享页头，保持身份、结果和预览的层次；研究功能不与管理导航混合 | 查询、消歧、快速预览、稳定深链接、返回原条件 |
| 药物与管线 | 药物分类与记录地区改为次要筛选；统一摘要、时间与零结果恢复 | 药物/项目口径、阶段/机构/权益、完整命中集格局 |
| 临床试验 | 分开常用药物/靶点与试验设计、联用、结果/发表；减少第一屏条件墙 | 招募/分期、药物角色、终点、评价、日期、订阅和详情 |
| 专利情报 | 统一查询摘要和零结果，不把空查询解读为无专利 | 专利族、法律状态、时间线、资产关联与来源 |
| 交易与公司 | 同一摘要，保留记录数和匹配口径 | 参与方、资产角色、金额/币种、权益与阶段 |
| 监管与安全 | 保留跨地区可比性限制，空记录明确边界 | 审批/认定/标签、安全事件和订阅 |
| 流行病学 | 次要人群/日期条件维持渐进披露；统一摘要 | 人群、地区、单位、观测区间与可比性 |
| 新闻与会议 | 统一已执行筛选和零结果恢复 | 事件类型、会议/发表日期、实体关联和保存检索 |
| 结构检索 | 保持编辑器与公开查询边界，时间标为查询时间 | 权威 SMILES、精确/子结构/相似性和 2D 展示 |
| 靶点档案 | 长标识自然换行，移动端不截断或撑宽；时间口径修正 | 关系、转化、活性/SAR、竞品和跨域证据 |
| 药物档案 | 零覆盖明细默认收起，缩短重复空状态留白；长名称完整换行 | 药物身份、研发项目、结构、里程碑和逐域缺失 |
| 公司档案 | 覆盖明细渐进披露，首屏聚焦管线与交易；长名称完整换行 | 机构角色、药物/项目、交易/监管/新闻 |
| 疾病档案 | 覆盖明细渐进披露，缩短无数据的重复提示；长名称完整换行 | 靶点、适应症、项目、人群和负担 |
| 通用实体档案 | 统一查询时间，不把原始 ID 当研发结论；长名称完整换行 | 公共身份、关系、事实和资料查证 |
| 对比列表 | 与监控、专题合并到“我的研究”的页面分类；对比矩阵明确查询时间 | 已选实体、服务器版本、差异与导出 |
| 监控与提醒 | “我的研究”分类，不再作为与检索并列的侧栏模块 | 保存检索、订阅、提醒及恢复原查询 |
| 知识专题 | “我的研究”分类，版本和引用能力保留 | 版本、claim 引用、关联实体和研究上下文 |
| 证据查证 | 与实体、结构查询合并到“情报检索”的页面分类 | 授权证据域、原文、页/段定位和稳定来源链接 |
| 用户中心/账号 | 账号、组织、退出仍在同一导航区域；共享页头去重 | 注册、登录、改密、邀请确认、组织隔离 |
| 数据工厂 | 空状态与非空列表各保留一个接入入口；“已配置”不冒充“已就绪” | 来源许可、运行图、预览、隔离、取消和恢复 |
| AI 审核 | 保持事实、身份、发布、质量等领域的单一实现；共享布局简化 | 引证、决策、冲突、审批、原子发布/撤回 |
| 商业运营 | 保留独立的管理导航和按功能加载，不混入研发事实 | 权益、账单、风险、争议与审计 |
| 企业管理 | 移除重复平台运营面板，组织管理仍留在原领域 | 组织、用户、邀请、组、访问、模型和审计 |
| 环境管理（新增） | 统一网关/主机检测、安装计划和运行/发布证据 | 默认离线、锁定配方、明确主机执行、最近安装和缺失证据 |

导航的检索方法、数据领域与个人研究工具已梳理为五个工作流，原十三个平铺入口的包含关系见[研究工作台架构](research-workbench-architecture.md)。所有原 URL、筛选和保存检索仍有效；分类栏不创建平行 hub 页面或第二份领域状态。详情沿用来源工作流高亮与原条件返回，账号不混入业务导航。

共享组件分别拥有导航、结果摘要、空结果、次要筛选和覆盖披露；七个查询页不再复制时间/分页摘要。企业平台面板只移动到环境模块，旧组件与旧入口删除，不增加另一套平台服务。环境依赖表保留组件、实际版本、明确项目要求和状态四列，共通检测说明只显示一次；缺失、版本不符或检查失败的具体原因直接可见，不被折叠隐藏。

## 缺失与后续边界

“模块不存在”和“当前授权数据未收录”要分开。对比、监控、知识和证据已经存在，但入口不够可发现，已补齐；环境检测/安装缺少受控链路，已新增。空组织没有事实时，界面必须展示缺失，不应通过示例数据或假进度填满。

真实数据的覆盖、来源更新频率、标识匹配、临床结果可比性、专利法律状态和金额披露完整性仍需由授权来源和数据责任人确认。毒理、ADMET、ELN、实验执行及预测模型运行不属于本次情报界面优化；没有数据和验收证据时不新增假模块或展示计算结论。

环境模块只管理本项目的锁定 Python/前端依赖与部署工具，不安装 WSL/系统 Docker，不自动重启共享服务。客户目标机器的完整离线介质、正式来源授权、远程 LLM、财务系统和生产高可用仍有独立门禁。操作及安全设计见 [环境管理](environment-management.md)。

## 验证方法

只运行改动和直接消费者的定向测试。研发审查场景注册在 `e2e/workspace/researcher-review.ts`，使用独立、明确标记的合成夹具和真实网关，在四个原定视口核对研究入口、五类身份档案、内部页面、筛选折叠草稿、页面溢出和网页不执行安装。等待实际业务内容加载后截图，加载动画不能作为页面验收证据。

合成记录只能证明导航、权限和界面行为，不能证明真实科学内容、来源覆盖或商业生产已验收。正式视觉参考使用仓库锁定 Chrome profile、原像素/性能门槛和审阅流程；定向 Chrome 运行不代替完整自动 CI。最终提交、PR、镜像和本地部署身份由交接证据另行记录，不能引用旧提交结果。
