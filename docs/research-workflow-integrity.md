# 研发工作流审计与升级

产品为 **X-Pharma / Apache-2.0**，软件版本以 [`pyproject.toml`](../pyproject.toml) 为唯一权威，按[贡献规范](../CONTRIBUTING.md#product-version-counter)的 PR 合并计数递增。本轮顺序为只读审计、方案/可行性、失败回归、实施、定向验收、GitHub CI/并线及精确主线部署；不把生产外部批准写成代码完成。

## 审计范围与证据边界

追踪五个研发工作流、专业查询及五类实体档案、证据/知识、内部运营与环境控制面的源码、URL、合同和领域权限。19 个顶层入口在一次性人员身份/SQLite/真实 Google Chrome 154.0.8037.97、1440×900 中检查，无整页横向溢出或脚本异常。非空保存研究、跨人员读取及并发修改另行复现；空页面检查不等于真实数据 UAT。原业务数据库、预览组织及其他服务不用于测试。

| 优先级 | 实际复现的缺陷 | 本轮处理 |
| --- | --- | --- |
| P1 | 有效旧列表超过目录前 100 条、或列表链接失效时，自动打开其他列表 | 详情只依赖明确的合法 URL ID；非法/无权/不存在显式失败，无 ID 才选择默认列表 |
| P1 | 列表写入迟到时把页面拉回旧目标 | 缓存更新与导航分离；请求绑定目标和生命周期，不再取得当前页面的控制权 |
| P1 | 监控消费者运行固定 v1，前端重放却使用最新 v2 | 主题/提醒各自读取持久化不可变版本；提醒保持事件原版本，不使用最新条件替代 |
| P1 | 共享后可读取私有阶段的历史说明和成员编号 | 历史仅所有者可读，当前共享详情仍按原授权可见；管理员不绕过所有者边界 |
| P2 | 列表表格输出所有外部 ID 的值，暴露内部/摄取编号 | 复用现有公共命名空间规则，并显示编号所属数据库 |
| P2 | 目录缺少搜索/分页，名称与说明无法在页面维护 | 新增唯一有界目录及版本化名称/说明编辑、只读有界历史 |
| P1 | 批量加入的版本预读可重复提交，离开页面后旧完成回调仍导航 | 同步锁覆盖预读至写入全过程，完成回调绑定原选择和页面生命周期 |
| P2 | 创建成功但成员失败后，新列表未被保留为重试目标 | 明确部分成功，保留新列表和选择；重试只加入成员，不重复创建 |
| P1 | 冲突后的版本刷新失败也被误报成功，并可能隐藏编辑草稿 | 验证真实刷新结果，网络失败保留草稿并明确诊断；权限/404 拒绝则隐藏旧详情 |

## 方案与可行性

实体、成员、SavedSearchVersion、ComparisonSetVersion、提醒原始条件、人员/租户权限均已存在。升级复用 PostgreSQL 权威服务、人员会话、生成 OpenAPI 客户端、TanStack Query 与唯一工作台路由，无新模型/数据源/收费依赖，无表结构变化、无历史数据重写或删除。

列表和批量加入使用同一目录服务/查询 hook；所有者过滤在服务器端先于分页。保留服务端旧数组 API 作为外部兼容，前端旧数组 wrapper/默认替换链已退出。纯展示分类不复制领域查询、许可或权限。

## 实现合同

- `GET /api/v1/comparison-sets/catalog`：有界 `q`、`limit`、`offset` 和 `editable_only`，授权过滤后返回完整命中总量，稳定排序后分页；字面 `%`/`_` 不作为通配符。
- `GET /api/v1/comparison-sets/{id}`：独立详情，目录过滤/分页不改写目标 ID。`PATCH`、成员批量操作和导出继续使用服务器期望版本与既有事务/许可。
- `GET /api/v1/comparison-sets/{id}/versions`：所有者、租户和人员会话保护，最大 100 条/请求，默认 50；`before_version` 向更早版本翻页。页面每次展示 10 项并按需读取，非所有者不呈现入口。
- `GET /api/v1/monitoring/topics/{id}/replay`：只读取调用人的主题固定版本。
- `GET /api/v1/monitoring/alerts/{id}/replay`：只读取接收人的提醒，并验证其保存检索 ID/原版本与主题关联；缺失或非法原条件、共享撤回、跨租户、非人员主体失败关闭。
- 重放输出仍是既有 `SavedSearchRead`，查询类型/JSON/版本来自不可变快照，更新时间来自该版本；名称等元数据不被宣称为历史业务快照。
- 409 不自动重试或覆盖。成功刷新才提示已刷新；失败时保留当前编辑草稿和明确恢复入口。401/403/404 不显示缓存旧详情。
- 列表写入、目录、成员/比较、导出、历史分别由独立模块负责；监控摘要与异步操作各有唯一所有者。共用紧凑目录控件和元数据模态，保留键盘焦点管理及白/灰设计，不新增顶层入口。

列表历史只是名称、说明、共享范围与成员编号的变更记录，不是当时的药物/临床/专利事实快照。实时对比仍通过现有专业档案/药物对比合同，缺少记录不被解释为不存在或实验结论。

## 定向验证与回退

回归先复现错误，再覆盖深链、迟到写入、选择隔离、目录、元数据、共享历史、冲突及网络恢复、批量预读/部分成功、主题/提醒原版本和角色/租户拒绝。只执行这些模块及直接消费者的定向测试、严格类型、生成合同检查与生产构建；未手工执行全仓库测试。原必需自动 CI、视觉预算、权限和清理门禁不放宽。

真实 Chrome 四视口使用一次性合成身份/记录，验证非空对比、版本历史、修改冲突、列表深链、缺失/非法链接、延迟响应、目录过滤、主题/提醒版本重放和当前共享权限。源码级、构建级、部署级与科学/生产验收分别记录，不把截图或合成数据库作为真实科研数据证明。

部署前在 E 盘保留配置/数据库恢复源和前一镜像标签，仅更新 `x-pharma-architecture` 应用容器；数据库 schema 不变，可回退原镜像，不撤回或删除用户研究。GitHub 普通并线及精确 main 部署、受影响路径复验之前不算交付完成。
